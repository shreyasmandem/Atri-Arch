# Deploying Atri Arch for free

Live now: **UI** https://atri-arch.vercel.app (static, Vercel) -> **API** https://atri-arch.onrender.com
(FastAPI in Docker, Render free plan). The two are separate so the UI is instant everywhere and the API can sleep.

## How it is wired

| Piece | Where | How it updates |
|---|---|---|
| UI (`frontend/`) | Vercel project `atri-arch`, root directory `frontend`, preset *Other* | every push to `main` |
| API (`Dockerfile`, `render.yaml`) | Render web service `atri-arch` (Blueprint, public repo) | **Manual Deploy -> Deploy latest commit** in the Render dashboard (a public repo has no push webhook) |
| API address the UI uses | `frontend/config.js` -> `window.AIP_API` | edit and push; ignored on localhost |

The API allows cross-origin calls from `https://*.vercel.app` (`CORS_ORIGIN_REGEX`) and from `CORS_ORIGINS`.

## Keys

The studio works **without any keys** (public demo mode): the brief agent falls back to its rules reader, and
the three judgement axes (coherence, brief fidelity, livability) are measured from the geometry. Adding model keys
makes the chat and the specialist critiques model-driven again, with the same fallbacks if a model is slow.

In Render -> `atri-arch` -> **Environment** add, as plain values (never commit them):

- `GROQ_API_KEY` (comma-separated for rotation)
- `GOOGLE_API_KEY`

then **Manual Deploy**. `SECRET_KEY` is generated by the Blueprint.

## Re-creating it from scratch

1. **Render** -> New -> Blueprint -> *Public Git Repository* `https://github.com/shreyasmandem/neathack-AtriArch`
   (uses `render.yaml`). Free plan; first build is a few minutes.
2. **Vercel** -> Add New -> Project -> import the repo, **Root Directory = `frontend`**, Application Preset = *Other*,
   no build command. Put the Render URL in `frontend/config.js` first.
3. Open the Vercel URL. The first request after the API has been idle takes about 50 s (the free instance wakes).

## Other hosts

- **Hugging Face Spaces**: Docker Spaces now need a paid plan; only Static Spaces are free, so the UI can live there
  but not the API.
- **Any Docker host**: the image is self-contained (`Dockerfile`, port from `$PORT`, default 7860).

## Notes

- Render's free instance has about 0.1 CPU: a full design takes about a minute there (about 30 s locally).
- SQLite lives in `backend/var` inside the container and resets on redeploy. Generated schemes are held in memory,
  so a design is only reachable on the instance that made it - fine for one demo user, and the reason the API is a
  single always-same instance rather than a serverless function.
- Never commit `backend/.env`.
